# 小红书「行程被打乱」帖采样：旅行者到底因为什么改行程（2026-11-09）

回答一个产品定义层的问题：**途迹的四类预案（下雨 / 排队太久 / 走不动了 / 某个点去不了）选对了吗，优先级该怎么排？** 之前这四类是自己拍的，这里拿公开帖子里旅行者自己说的原因来对。结论见 `summary.md`。

## 结论（摘要）

读了 203 篇，人工归因，得到 101 篇「真的改了行程」的帖子（行中变更 60、行前取消或改期 41），另有应对指南 17、非变更 85。

| 行中变更的原因（60 篇，多选） | 篇数 | 占比 | 途迹现有预案 |
|---|---|---|---|
| 交通延误取消（航班 / 火车 / 渡轮 / 误机） | 31 | 52% | 没有，但后果「到晚了、当天时间被压缩」正是行中模式「现在几点」重排管的事 |
| 天气（雨、台风、大雾、酷热） | 22 | 37% | 下雨预案 |
| 体力 / 生病（累瘫、感冒发烧、高反、受伤） | 12 | 20% | 走不动了预案 |
| 时间安排（起晚、堵车、逛太久） | 6 | 10% | 行中模式可部分覆盖 |
| 同伴 / 个人事务 | 5 | 8% | 产品范围外 |
| 闭馆 / 约不上 / 停运 / 封路 | 4 | 7% | 某个点去不了预案 |
| 排队 / 人多 | 2 | 3% | 排队太久预案 |

- 四类预案至少覆盖一条原因的行中变更 34/60（57%）；一条都不覆盖的 26 篇，几乎全是交通延误取消。
- 行前取消的前三是同伴 / 个人事务 49%、交通取消 29%、生病 24%，这部分在途迹范围外。
- 去掉带原因的查询「下雨 行程 怎么办」后，行中变更里天气从 37% 降到 27%，交通升到 58%，排序不变。

**对预案优先级的含义**：按帖子里的出现率，下雨 > 走不动 > 去不了 > 排队，而不是现在四类并列；交通延误本身超出一个城市行程工具的范围，但它的后果（到得晚、当天只剩半天）应该有一个显眼的入口直接进行中模式重排，而不是让用户自己去找「现在几点」。这两条都还没改进产品。

## 采样口径

- **平台与方式**：小红书网页版，登录态（用户本人扫码），内置浏览器半自动翻页与读取；不调接口。每篇只保留笔记 id、点赞、来源查询、标题、正文字数、是否视频、关键词命中数，以及我读完正文后写的一句概括；**不存正文**。
- **查询**（六个，综合排序，各滚动 5 页，结果池 71–100 张卡，合并去重 516 张）：旅游 行程被打乱、旅行 计划赶不上变化、旅游 攻略白做了、旅游 突发状况 行程、旅游 临时改行程，以及大王建议的「下雨 行程 怎么办」（带原因，单独打标）。没用大王原话里的「行程 被打乱」，因为不带「旅游」时结果全是心理学帖。
- **取样**：六个查询的结果轮流交错排序（不按点赞排，避免只剩情绪帖），三个标签页并行按序打开，读到变更帖满 100 为止，共 203 篇。
- **分类**（单人人工，读标题 + 正文前 260 字 + 全文关键词命中）：
  - 类型：行中变更（旅途中改了行程，含出发日误机）/ 行前取消或改期（出发前就没去成）/ 应对指南（教人怎么办，没有具体事件）/ 非变更（感想、攻略、求推荐、非旅行）。
  - 原因（多选）：W 天气、C 闭馆 / 约不上 / 停运 / 封路、Q 排队 / 人多、B 体力 / 生病、T 交通延误取消、S 时间安排、P 同伴 / 家人 / 工作、M 兴致变化 / 踩雷、X 安全 / 政策 / 罢工 / 第三方取消、O 其他或未说明。
- **关键词自动标注只能初筛**：和人工逐原因比对一致率 46%，「朋友」「取消」这类词大量误命中，漏标最多的是体力 / 生病。

## 要主动说的局限

- **发帖偏置**：航班取消涉及钱和维权，值得发帖；排队、闭馆太日常，少有人专门发。帖子里排队只占 3%，不等于现实里只占 3%。
- **出境游偏多**：样本里美国、欧洲、日本的帖子占了大头，航班问题被放大；途迹是国内城市 2–4 日行程，机场只在首尾各一次。
- 单人标注、203 篇、阈值和分类都是本次定的；「下雨」查询带原因，已单独剔除对比。
- 只读了文字，行程只在图片里的帖子算不出原因（计入非变更或仅标题）。
